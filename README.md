# Shiva Sai Thota — Portfolio

A Next.js portfolio featuring a 3D technology keyboard, projects, experience, education, resume download, and a Formspree contact form.

## Run locally

Use Node.js 22.13+ and npm 11+.

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

Open http://localhost:3000. If `.env.local` already exists, edit it instead of overwriting it. Use npm and the committed `package-lock.json` for dependency management.

## Project structure

```text
src/
  app/                    Pages, metadata, and global styles
  assets/projects/        Compressed project covers imported at build time
  components/
    contact/              Contact form and email link
    effects/              Particles, cursor, and reveal animations
    keyboard/             Three.js scene, controls, and scroll movement
    layout/               Header, footer, providers, theme, and smooth scrolling
    preloader/            Welcome screen and loading coordination
    sections/             Home page sections and project cards
    ui/                   Shared buttons, badges, cards, and form fields
  data/                   Editable profile, navigation, projects, and technology data
  lib/                    Formspree submission and class-name utility
public/
  assets/                 Photo, logos, font, keyboard sounds, and artwork sources
  Shiva_Sai_Software_Engineer.pdf  Resume download
  terminal.svg            Terminal-style site icon
scripts/                  Source, asset, dependency, page, and keyboard checks
tests/                    Contact submission, keyboard pointer, and audio tests
```

The `app` files assemble pages. Components render the interface, `data` holds content, and `lib` holds small reusable functions. Styles sit next to the components they style; all styles use plain CSS and Tailwind.

`node_modules/` contains installed dependencies. `.next/` contains generated application files and TypeScript caches. Both are ignored by Git. Keep `.env.local` private; `next-env.d.ts` is generated by Next.js.

Crebry, Edith, and Decentralized Stablecoin are Personal projects. Bhagyashree Ventures and GreenCost are Freelancing projects. All five use screenshots of the supplied websites.

Project covers are pre-compressed WebP files, imported at build time with a small blur preview. Cards and detail dialogs share the same cached image URL, avoiding on-demand image conversion and duplicate downloads. Keep below-the-fold cards lazy-loaded; the standalone projects page loads its first cover eagerly.

The keyboard keeps one Three.js scene while scrolling between sections. The complete 50-key layout uses 10 columns × 5 rows on desktop and 5 columns × 10 rows on phones. Redux is included based on the ReduxLearning project. Hovering or sliding a finger presses successive keys and plays their sounds; lifting or cancelling the gesture releases the key. Page scrolling remains available outside the keyboard. DOM controls provide keyboard access and the same touch gestures when WebGL is unavailable. Below 1024px, it becomes a translucent background in the hero. The loader waits for the first scene frame, then reveals the hero content and keyboard. Reduced-motion preferences are respected.

Logo and screenshot origins are recorded in the two `sources.json` files under `public/assets/`. Keep these records when replacing or adding artwork.

Keyboard audio preloads both samples into one Web Audio context. The first click, tap, or keypress anywhere on the page unlocks playback; fresh visits show “Enable sound” until the browser permits it. Muting remains in effect during later interactions. The same gesture handling retries audio after a browser interruption, without needing an off/on toggle.

## Contact form

1. Create a form at https://formspree.io/ and set its email notification recipient to `shivasaiyadav0803@gmail.com`. Complete Formspree's email verification if requested.
2. Copy the ID from the endpoint. For `https://formspree.io/f/abcdefgh`, use `abcdefgh`.
3. Set `NEXT_PUBLIC_FORMSPREE_ID=abcdefgh` in `.env.local` and restart the development server.
4. Set the same variable in production hosting settings, then rebuild or redeploy.
5. Submit the form and check the Formspree dashboard and your inbox.

The browser sends `name`, `email`, and `message` directly to Formspree. The form ID is public. No mail password, secret API key, or custom email API is needed. Configure validation and spam protection in the Formspree dashboard. The form resets after success, keeps the message after failure, and offers a mail icon as an alternative. Without a form ID, sending is disabled.

Official setup: https://formspree.io/html/

## Optional settings

- `NEXT_PUBLIC_SITE_URL=https://shivasai.is-a.dev`: canonical production origin. Missing, malformed, or different origins fall back to this domain; Vercel aliases cannot leak into metadata.
- `GOOGLE_SITE_VERIFICATION`: optional Google HTML-tag verification token (the `content` value only).
- `BING_SITE_VERIFICATION`: optional Bing HTML-tag verification token (the `content` value only).
- `UMAMI_DOMAIN` and `UMAMI_SITE_ID`: analytics, enabled only when both are set.

Public environment values are included during the build. Rebuild after changing them.

## Maintain and verify

```powershell
npm run format
npm test
npm run lint
npm run typecheck
npm run check:unused
npm run build
npm audit --omit=dev
```

`check:unused` checks the source import graph, stylesheet references, CSS-module classes, public assets, and runtime/development dependencies. Missing asset paths and local imports also fail the check. Artwork provenance records are explicitly retained.

Typechecking validates Next.js's generated route types and separately checks application source for unused locals. Tests mock Formspree and never send email. Pointer-input tests cover touch sliding, release/cancellation, multiple fingers, mouse hover/drag, and listener cleanup. Audio tests cover initial unlocking, touch-end retries, sample playback, muting, interrupted contexts, loading failures, and cleanup.

With a server running on port 3000:

```powershell
npm run verify
node scripts/verify-keyboard.mjs
```

Use `npm start` to serve the production build. Real email delivery requires your Formspree form ID and recipient configuration.

## Search indexing and deployment

The four public pages have unique server-rendered titles, descriptions, canonical URLs, Open Graph and Twitter metadata. `/sitemap.xml` lists only those pages; `/robots.txt` allows public crawling. Sitemap entries deliberately omit unverified modification dates. The existing 1200 × 630 `/opengraph-image` is shared by all routes. JSON-LD describes the verified person, website, and About profile page.

Only the old `shiva-sai.vercel.app` hostname gets a permanent redirect to `https://shivasai.is-a.dev`, preserving paths and query parameters. No `www` redirect, DNS change, or Vercel domain change is made. Other preview deployments use the primary canonical URLs; keep Vercel's preview indexing protection enabled. Canonical tags are signals, not guarantees of which URLs a search engine indexes.

### Google Search Console

1. In [Search Console](https://search.google.com/search-console), add a **URL-prefix** property for `https://shivasai.is-a.dev/`.
2. Choose **HTML tag** verification. Copy only the `content` token into `GOOGLE_SITE_VERIFICATION` in Vercel's Production environment variables. Do not put an entire meta tag in the variable.
3. Set `NEXT_PUBLIC_SITE_URL=https://shivasai.is-a.dev`, then redeploy. Verification tokens are embedded at build time. Keep the token configured after verification.
4. View the deployed homepage HTML and confirm `google-site-verification` is present. Return to Search Console and click Verify.
5. In **Sitemaps**, submit `https://shivasai.is-a.dev/sitemap.xml`.
6. Use **URL Inspection → Test live URL** on Home, About, Projects, and Contact. Request indexing when the live test succeeds. Check the selected canonical and Page indexing reports after recrawling.

A Domain property uses DNS verification instead of the HTML tag. No DNS changes are needed for the URL-prefix method above. See [Google's verification documentation](https://support.google.com/webmasters/answer/9008080).

### Bing Webmaster Tools

1. Sign in at [Bing Webmaster Tools](https://www.bing.com/webmasters/).
2. Import the verified Search Console property, or add `https://shivasai.is-a.dev/` manually.
3. For manual HTML-tag verification, put Bing's `msvalidate.01` content token in `BING_SITE_VERIFICATION` in Vercel Production, redeploy, then verify in Bing.
4. Submit `https://shivasai.is-a.dev/sitemap.xml` in Bing's Sitemaps section and use URL Inspection to review the four public URLs.

After deployment, check the live sitemap, robots file, canonicals, redirect from the old hostname, and preview at `/opengraph-image`. Test social sharing with LinkedIn Post Inspector and Facebook Sharing Debugger; services may cache earlier previews. Validate JSON-LD with [Schema.org Validator](https://validator.schema.org/) and [Google Rich Results Test](https://search.google.com/test/rich-results). Schema markup does not guarantee a rich result or indexing. Use PageSpeed Insights and Search Console's Core Web Vitals report for production measurements; no field-performance score is claimed by the local checks.
